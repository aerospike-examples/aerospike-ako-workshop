# Section 04 — All-flash Storage

## Section takeaway

Run an Aerospike namespace whose **primary index lives on local NVMe** instead of DRAM, and see what that costs: paired index/data partitions on every disk, kernel `vm.dirty_*` settings on every node, and a `partition-tree-sprigs` value fixed at deploy time.

## Labs in this section

| Lab | Title | Duration | Depends on |
|-----|-------|----------|------------|
| 4.1 | Deploy an all-flash cluster | ~25–35 min | Setup step 0.8 |
| 4.2 | Scale an all-flash cluster | ~25–35 min | 4.1 |

See [LAB_REGISTRY.yaml](../../LAB_REGISTRY.yaml) for machine-readable metadata.

## Recommended order

```text
0.8 (setup) → 4.1 → 4.2
```

Section 4 is **optional, off by default, and self-contained**. A default `setup-all.sh` run does not create its cluster. It needs only Section 0 (for `secrets/features.conf` and your cloud credentials) and runs entirely on its own cluster, so it can be taught at any point after Section 0 — or skipped without affecting Sections 1–3. Setup step 0.8 installs AKO **4.5.0** (`ALL_FLASH_AKO_VERSION`); it does not follow the main cluster's 4.2.0 → 4.5.0 upgrade ladder.

## Dedicated cluster

Every lab here runs on `${ALL_FLASH_CLUSTER_NAME}` (default `my-cluster-all-flash`), created by opt-in setup step **0.8**:

```bash
./scripts/setup/setup-all.sh --step 0.8
./scripts/lib/kubecontext.sh all-flash    # switch to it
./scripts/lib/kubecontext.sh main         # switch back
```

A default `setup-all.sh` run does **not** create it — it is a third cluster with large NVMe instances. See [Lab 0.8](../00-environment-setup/08-all-flash-cluster.md) for what the bootstrap does.

| Cloud | Machine | Local flash | Aerospike pods |
|-------|---------|-------------|----------------|
| AWS EKS | `i8ge.3xlarge` (12 vCPU / 96 GiB) | 1 × 7500 GB NVMe | 3 → 4 |
| GCP GKE | `n2-highmem-16` (16 vCPU / 128 GiB) | 16 × 375 GiB Local SSD | 3 → 4 |

Both end up with the same per-node budget: **600 GiB of primary index on flash**.

## Scope

- **In scope:** `index-type: flash` with `mounts` / `mounts-budget`; paired index (Filesystem) and data (Block) NVMe slices; the kernel settings all-flash requires; horizontal scale 3 → 4.
- **Out of scope:** converting an existing DRAM-index cluster in place (AKO cannot add the index volumes to a running CR), secondary index on flash, rack awareness, TLS, Karpenter on this cluster, and raising `partition-tree-sprigs` (cold restart — instructor note only).

## Deploy path

Unlike the Lab 2.6 upgrade-lab, this cluster honors `DEPLOY_PATH`, so Path A (kubectl) and Path B (Helm) both work end to end. The CR and the Helm values are **provider-specific** because EKS pairs 5 data volumes with 1 index mount while GKE pairs 16 with 16 — Lab 4.1 bases, Lab 4.2 scale CRs, and Helm bases are generated by [render-all-flash-manifests.py](../../scripts/labs/render-all-flash-manifests.py).
